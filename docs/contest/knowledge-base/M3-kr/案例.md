# M3 知识表示与推理 · 案例

## 案例一：医疗专家系统 MYCIN（1970s）

**背景**：MYCIN 是斯坦福大学开发的早期著名专家系统，用于辅助诊断血液感染类疾病并推荐抗生素治疗方案，是产生式系统 + 不确定性推理的经典代表。

**技术点**：
- **知识表示**：约 600 条产生式规则，形如 `IF 细菌染色为革兰氏阴性 且 形态为杆状 THEN 可能有概率 0.8 是 Enterobacteriaceae`。
- **推理机**：采用后向链——从"需确定致病菌"目标反推需要哪些临床证据，再向用户提问。
- **不确定性**：用**确定性因子（Certainty Factor, CF）**在 $[-1,1]$ 表示证据支持/反对程度，并定义规则组合与证据合成公式。

**启发**：
1. 专家系统的价值在于把稀缺专家经验**显式编码、可复用、可审计**，这正是"知识表示"的实用意义。
2. 其失败教训同样深刻：规则维护成本高、获取难（知识工程瓶颈）、难以覆盖真实世界不确定性，最终导致专家系统商业化退潮。
3. 素养启示：可解释、可追责在医疗等关键领域至关重要——今天的大模型仍面临"黑箱不可解释"的同类挑战，MYCIN 的思路（显式规则+置信度）仍被监管场景借鉴。

## 案例二：知识图谱赋能搜索与问答（以 Wikidata/Google 知识图谱为例）

**背景**：现代搜索引擎（如 Google 的 Knowledge Graph）不再仅返回链接列表，而是直接给出结构化答案（"爱因斯坦的导师是谁？"→"阿尔弗雷德·克莱纳"），背后是海量三元组知识图谱。

**技术点**：
- 知识以三元组存储：$(h,r,t)$，如 `(阿尔伯特·爱因斯坦, 导师, 阿尔弗雷德·克莱纳)$。
- 查询可转化为图模式匹配（SPARQL）或结合嵌入（TransE 等）做链接预测。
- 与 NLP（M6）结合：先把自然语言问句解析为实体与关系，再在图谱上检索。

**启发**：
1. 知识图谱把"零散文本"组织成"可机器推理的关系网"，是符号表示在大数据时代的复兴。
2. 它补足了纯深度学习"知其然而不知其所以然"的短板——答案可追溯来源、可解释。
3. 思政映射：知识图谱作为数字基础设施，其数据主权、构建公平性（如文化偏见）是值得关注的问题，呼应 M9 的伦理议题。

> 小结：从 MYCIN 的规则库到当代知识图谱，符号主义证明——把知识"讲清楚、存规范、推得动"，是智能系统可靠可控的基石，也是与统计学习互补的关键一极。
