## 二、D1 需求规格说明书（需求层面）

**目标**：深入新时代大学生的学习需求，结合前沿 AI 应用场景，完成系统性需求分析，明确技术与需求的结合点。

```
1. 引言
   1.1 编写目的与读者对象
   1.2 项目背景（KnowSubtle 系统定位、参赛目标）
   1.3 术语与缩略语（智能体 / LLM / SSE / 多智能体编排 / RAG）
   1.4 参考文档（GB/T 8567、MetaGPT 论文、教育部 AI 素养框架）

2. 新时代大学生的学习需求调研
   2.1 调研背景：AI 原生一代（Gen-AI）的学习行为变迁
   2.2 调研方法（三角验证）
       - 文献/政策研究（AI 素养、个性化学习理论）
       - 竞品分析（主流学习平台/AI 辅导工具的能力缺口）
       - 用户访谈与问卷（样本量、维度设计、画像聚类）
   2.3 核心痛点（数据 + 案例）
       - 痛点A：学习路径"千人一面"，缺乏个性化
       - 痛点B：资源碎片化，难以按目标聚合
       - 痛点C：被动接收，缺少对话式引导与即时反馈
       - 痛点D：AI 工具与课程体系割裂，不会"用 AI 学"
   2.4 用户画像与典型场景（本科生 / 跨专业自学者 / 备考者）
   2.5 需求优先级（MoSCoW：Must/Should/Could/Won't）

3. 功能性需求
   3.1 学习画像：对话式采集 + 结构化画像（FR-01）
   3.2 资源中心：7 类多智能体生成（概念/案例/习题/路径/答疑/实验/拓展）（FR-02）
   3.3 学习路径与精准推送（FR-03）
   3.4 评估与反馈闭环（FR-04）
   3.5 账号体系与数据隔离（FR-05）

4. 非功能性需求
   4.1 性能（核心功能响应、流式首字延迟）
   4.2 安全与内容合规（防幻觉、敏感过滤、账号隔离）
   4.3 可用性与可访问性（离线可用、无 CDN 依赖）
   4.4 可维护性与可扩展性（智能体可插拔）

5. 前沿 AI 技术与需求的结合点（核心章节）
   5.1 LLM 个性化导师 ↔ 痛点C/D
   5.2 多智能体协作编排 ↔ 痛点B（资源聚合）
   5.3 流式呈现（SSE）↔ 非功能性能（避免白屏）
   5.4 防幻觉 + 内容安全 ↔ 非功能安全
   5.5 知识库/RAG 雏形 ↔ 痛点A（按课程定制路径）

6. 系统边界、假设与依赖
```

**需求层面达标自检**：§2 提供调研方法+痛点+画像（数据与案例）；§5 明确"技术与需求结合点"，逐条映射到痛点。

## 三、D2 系统设计说明书（技术开发层面）

**目标**：详细阐述智能体的设计、开发、测试、部署全流程，含 UI、功能实现、系统集成与优化；重点说明前沿 AI 融合思路、实现方法、创新实践与 UX 提升。

```
1. 总体架构设计
   1.1 分层架构（前端 SPA / 后端 FastAPI / 智能体层 MetaGPT / 存储层）
   1.2 系统总体架构图（Mermaid，见 §九 图表清单 G1）
   1.3 关键技术选型与决策记录（ADR：为何 FastAPI / 单文件 SPA / MetaGPT stub）

2. 智能体设计与实现
   2.1 智能体拓扑：6 后端 Agent + 18 Action（系统现状）
   2.2 个性化学习智能体（用户级 4 表：student_profiles / resource_items
        / personalized_paths / evaluation_records，全隔离）
   2.3 多智能体协作流程与时序图（G2）
   2.4 智能体开发约束（MetaGPT stub 打桩，DEMO_MODE 不触碰生产逻辑）

3. 前沿 AI 技术融合应用（核心章节）
   3.1 真实 LLM 代理层
       - call_llm（非流式）/ call_llm_stream（async generator 逐 delta）
       - 服务端代理 OpenAI 兼容 /chat/completions，Key 不落地
   3.2 流式呈现（SSE + StreamingResponse）
       - 端点：/api/profile/converse/stream、/api/resources/generate/stream
       - 事件设计：token / profile / safety / progress(start|error|done) / resource / done / error
   3.3 防幻觉机制
       - 系统提示注入（不确定标 [待核实]、不编造引用、拒学术不端）
       - 资源内容追加免责脚注 RESOURCE_FOOTNOTE
   3.4 内容安全过滤（moderation.py 离线启发式 9 类：政治/违禁/色情/暴力/仇恨/
       自伤/诈骗/隐私正则/学术不端）
   3.5 多模态资源卡片化（类型图标/智能体/难度★/格式/flagged 角标）

4. 用户界面（UI）设计
   4.1 设计规范（玻璃拟态 .glass、三标签导航、深色背景消白闪）
   4.2 关键界面（学习画像对话 / 资源流式生成 / 学习路径图）
   4.3 交互流程图（G3：画像采集；G4：资源流式生成时序）
   4.4 响应式与离线（无第三方库、无 CDN）

5. 系统集成与部署
   5.1 前后端契约（API 表：11 非流式 + 2 流式端点，Bearer 鉴权）
   5.2 鉴权与隔离（user_scope_middleware、current_user_id contextvar）
   5.3 打包与桌面端（PyInstaller onedir → KnowSubtle.exe；PyQt6 + QWebEngineView；
       GPU 合成渲染 KS_* 开关；单实例 PID 锁）
   5.4 持续集成（verify.yml：ubuntu 跑 verify_all + verify_live2；
       windows 构建 exe 跑 test_exe）

6. 优化策略
   6.1 性能（content-visibility、移除 will-change、scroll 容器优化）
   6.2 渲染（GPU 光栅 + 合成，解决上下滑动卡顿）
   6.3 首字延迟（流式替代白屏）

7. 创新实践与 UX 提升策略（凝练章节）
   7.1 对话式画像替代表单填写
   7.2 多智能体资源工厂（一次生成多类型资源）
   7.3 流式 + 进度追踪（零白屏）
   7.4 防幻觉 + 内容安全双保险（学术合规）
   7.5 开源协议显著标注（ATTRIBUTION.md，含 PyQt6 GPLv3 商业许可提示）
```

**技术开发层面达标自检**：§2 设计、§3 开发（含 AI 融合）、§5 部署、§6 优化、§7 创新/UX，闭环覆盖"设计-开发-测试-部署全流程"。
